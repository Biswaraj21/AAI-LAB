# =============================================================================
# input.txt  —  Garage Scheduler Input File
# =============================================================================
#
# HOW TO RUN:
#   python garage_scheduler.py --input input.txt
#   python garage_scheduler.py --input input.txt --seed 42
#   python garage_scheduler.py --input input.txt --verbose
#
# =============================================================================
# FORMAT OVERVIEW
# =============================================================================
#
# LINE 1  :  N  M  k  [seed]
#              N    = number of car TYPES
#              M    = number of mechanics  (named M1, M2, ... MM)
#              k    = fatigue limit (break after k consecutive tasks)
#              seed = optional integer for reproducible runs (omit = random)
#
# -----------------------------------------------------------------------------
# CARS SECTION  (N blocks, one per car type)
# -----------------------------------------------------------------------------
# Each block starts with:
#   CAR <name>  <num_instances>
#       <name>          = car type label, e.g. C1, C2, Sedan, SUV …
#       <num_instances> = how many cars of this type to service today
#
# Followed by the DAG in ADJACENCY-LIST (linked-list) format:
#   TASK <task_id>  [->  <child_id>:<prob>  <child_id>:<prob>  ...]
#
#   • <task_id>  names follow the pattern:
#         Root tasks          : A1, A2, B1, B2 …  (any alphanumeric label)
#         Sub-tasks of A1     : A11, A12, A13 …
#         Sub-tasks of A11    : A111, A112 …
#         (depth is unlimited; just keep appending a digit)
#
#   • The  ->  part lists every child that MIGHT be spawned when this task
#     completes, together with its spawn-probability threshold:
#         roll > prob  →  child task IS spawned      (high prob = rare spawn)
#         roll ≤ prob  →  child task is NOT spawned  (low  prob = common spawn)
#
#   • A task with NO  ->  part is a LEAF (it never spawns anything).
#
#   • ARRAY-LIST shorthand: instead of one TASK line per node you can write
#     all children of the same parent on a single line:
#         TASK A1 -> A11:0.3  A12:0.5  A13:0.7
#
# =============================================================================
#
# EXAMPLE DAG (Sedan):
#
#   Root tasks A1 and A2 are always scheduled.
#   Completing A1 may spawn A11 (70% chance) and/or A12 (50% chance).
#   Completing A11 may spawn A111 (60% chance).
#   A2 and A12 are leaves — they never spawn anything.
#
#   Adjacency list:
#       TASK A1  ->  A11:0.30  A12:0.50
#       TASK A11 ->  A111:0.40
#       TASK A111                          ← leaf
#       TASK A2                            ← leaf
#       TASK A12                           ← leaf
#
# =============================================================================
